Total: 11 files, 248 KB. Largest: 70.2 KB (budget was about 300 KB per asset).

**Why WebP only:** AVIF was encoded too (`--avif`). It saved up to 49 percent on the card back but came out larger for felt-landscape, about 40 KB less in total (208 KB vs 248 KB). Shipping both formats would put both into the offline cache (the service worker precaches every public file). So the 40 KB saving did not justify the second copy. Every browser that runs the app reads WebP.

## Where each asset goes, and its fallback

| Place | How | If the image does not load |
|---|---|---|
| Room | fixed `body::before` layer (iOS ignores `background-attachment: fixed`), darkened 50 to 90 percent from top to bottom so text stays readable | the v4 CSS room gradient underneath |
| Table cloth | `.felt.theme-emerald` (the default theme). The CSS brass rail stays, because the table shape changes with the screen. A dark veil at top and bottom, plus a text shadow on labels written on the cloth | the v4 CSS cloth gradient underneath. Sapphire and bordeaux keep their CSS cloth |
| Card back | `backImage()` in `apps/web/src/art.ts`: WebP layer over the original `classic.svg`. The CSS "21" medallion is hidden, because the art has its own | `classic.svg` (second background layer); previews swap to the SVG on error |
| Chips | `.chip.t1` to `.t5`, stake buttons `.stake-chip.tier-1` to `-5` | the solid tier colour underneath |
| Coffee gift | `GiftIcon` renders the WebP for `coffee` | the original SVG coffee icon (`onError`) |

The coffee art is used only as the coffee gift icon, at the same size as the other gift icons. It does not appear as decoration on the table, and it never catches taps.

## Page weight and LCP, before and after

Method: `scripts/perf-measure.mjs`, run as follows:
- cold Chromium, no HTTP cache, no service worker, mobile emulation;
- two networks: unthrottled, and "slow 4G" (1.6 Mbps, 150 ms RTT, 4x CPU);
- two pages: the first-visit page (`/`) and a 3-player table (`/#/lab/three`);
- raw data in `docs/perf-before-2026-11-01.json` and `docs/perf-after-2026-11-01.json`.

| Slow 4G | Before: weight | Before: LCP | Art only: weight | Art only: LCP | After (art + compression): weight | After: LCP |
|---|---|---|---|---|---|---|
| First visit, portrait | 646 KB | 3.58 s | 683 KB | 3.89 s | 254 KB | 1.86 s |
| First visit, landscape | 646 KB | 3.60 s | 674 KB | 3.80 s | 244 KB | 1.88 s |
| Table, portrait | 671 KB | 3.70 s | 825 KB | 5.00 s | 401 KB | 2.96 s |
| Table, landscape | 671 KB | 3.76 s | 801 KB | 4.87 s | 377 KB | 2.77 s |

**What happened:**
- **The art alone made the table slower.** It added about 150 KB of images, and the felt became the largest paint.
- **The fix: compression.** The server had been sending the 511 KB script uncompressed. The build now writes `.br` and `.gz` next to every text file (`apps/web/vite.config.ts`, `precompress`), and Fastify serves them (`preCompressed: true`). The script went from 511 KB to 136 KB on the wire.
- **Net result:** lighter and faster than before the art on every row.
- **Unthrottled LCP:** 0.2 to 0.3 s before and after.
