# Data model plan (Stages B to E)

> **סיכום לעוז:** זה מפרט טכני של הטבלאות שיתווספו לבסיס הנתונים הקיים, בלי ליצור מערכת כספים שנייה.
> הקוינס ממשיכים לעבור רק דרך יומן הארנק (`ledger`) הקיים, ומוסיפים לו סוגי תנועות ומקורות.
> XP הוא טבלת התקדמות נפרדת, והוא לא מטבע ולא ניתן לקנייה.
> כל טבלה מקבלת מפתח ייחודי שמונע זיכוי כפול, וכל מיגרציה נוספת היא בשלבים קטנים.

Baseline: `apps/server/migrations/001_init.sql` (users, sessions, wallets, ledger, grant_claims, groups, group_members,
friendships, rooms, seats, rounds, settlements, hand_results, commands, matches, match_entries).
Only `gift_events` (002) is part of the current branch; everything else is planned.

## Principles

- One money system: `wallets` + `ledger`. New money flows add `ledger.kind` values and source columns, never a new ledger.
- Every credit is idempotent: a unique business key (claim id, transaction id, mission period) plus `ledger.idem_key`.
- Wallet changes lock the wallet row (`select ... for update`) in the same transaction as the rule check.
- Additive migrations only (new tables, nullable columns, widened check constraints). No destructive change without a
  backup and a tested rollback script.
- Times stored UTC; calendar boundaries computed in Asia/Jerusalem on the server; never the client clock.

## Tables

### 002 gift_events (Stage B, this branch)
```
id text pk
room_id text not null references rooms(id)
sender_id text not null references users(id)
recipient_id text not null references users(id)
gift_id text not null            -- catalog key: coffee, tea, cookie, rose, trophy, tissue
client_event_id text not null    -- generated by the sender's client
created_at timestamptz not null default now()
expires_at timestamptz not null  -- created_at + 45 s
unique (sender_id, client_event_id)           -- retry does not create or rebroadcast a second gift
index (room_id, expires_at)
```
No ledger rows in Stage B (gifts are free). Later paid or inventory gifts debit the sender in the same transaction as the
insert, with `ledger.idem_key = 'gift:' || id`. The recipient is never credited.

### 004 auth_identities, blocks, users/sessions columns (Stage C)
```
auth_identities(
  id text pk, user_id text not null references users(id),
  provider text not null check (provider in ('google','apple','facebook','test')),
  subject text not null,               -- provider 'sub'; never the email
  email text, email_verified boolean,  -- informational only, never used to merge accounts
  linked_at timestamptz not null default now(), last_login_at timestamptz,
  unique (provider, subject), unique (user_id, provider)
)
blocks(blocker_id text, blocked_id text, created_at timestamptz, primary key (blocker_id, blocked_id), check (blocker_id <> blocked_id))
```
`provider = 'test'` rows are only accepted when the server runs with a test flag that production builds refuse to set.
Deletion: `users.status = 'deleted'`, identities and sessions removed, display name replaced, ledger and hand results kept
anonymized where retention is required (documented in docs/AUTH_AND_FRIENDS.md).

### 005 catalog_items, inventory (Stage D)
```
catalog_items(id text pk, kind text check (kind in ('card_back','chip_set','table_theme','frame','title','gift')),
  rarity text, price_units bigint null, earn_rule jsonb null, active boolean, version int)
inventory(user_id text, item_id text references catalog_items(id), source text check (source in
  ('unlock','mission','reward','season','purchase','grant')), source_id text, acquired_at timestamptz,
  primary key (user_id, item_id))
```
Coin purchases of cosmetics: one transaction inserts inventory and a `ledger` row `kind = 'cosmetic_purchase'`,
`idem_key = 'cosmetic:' || user_id || ':' || item_id`. The primary key prevents buying the same item twice.
Migration seeds existing unlocks (classic, brass, midnight, emerald, sapphire, bordeaux) and backfills inventory from
hand counts so nobody loses an item.

### 006 reward_definitions, reward_claims, mission_progress, xp (Stage D)
```
reward_definitions(id text, version int, kind text check (kind in ('wheel','scratch','mission','season')),
  table jsonb not null,   -- visible outcomes and weights; published to clients as-is
  active_from timestamptz, active_to timestamptz, primary key (id, version))
reward_claims(id text pk, user_id text, definition_id text, definition_version int,
  period_key text not null,             -- e.g. wheel:2026-11-01 (Jerusalem date), scratch:welcome
  outcome jsonb not null,               -- chosen server-side with crypto RNG, stored before any animation
  ledger_id bigint null, inventory_item text null,
  created_at timestamptz, revealed_at timestamptz null,
  unique (user_id, definition_id, period_key))
mission_progress(user_id text, mission_id text, period_key text, progress int, target int,
  completed_at timestamptz, claimed_at timestamptz, primary key (user_id, mission_id, period_key))
mission_events(user_id text, mission_id text, period_key text, source_event_id text,
  primary key (user_id, mission_id, period_key, source_event_id))   -- a hand result counts once
xp_events(id bigserial, user_id text, amount int check (amount > 0), source_type text, source_id text,
  unique (user_id, source_type, source_id))
user_progress(user_id text pk, xp bigint, level int, updated_at timestamptz)
```
Claim flow: lock wallet, insert reward_claims (unique key decides once), insert ledger row with
`idem_key = 'reward:' || claim.id`, commit, then the client animates to the stored outcome. A second device or a refresh
reads the existing claim. Changing a prize table creates a new version; claims keep the version they used.

### 007 seasons (Stage D)
```
seasons(id text pk, name text, starts_at, ends_at, tiers jsonb, premium_product_id text null)
season_progress(user_id, season_id, xp int, tier int, premium boolean default false, primary key (user_id, season_id))
season_tier_claims(user_id, season_id, tier int, track text check (track in ('free','premium')),
  claimed_at, primary key (user_id, season_id, tier, track))
```

### 008 purchases, entitlements, ledger origin (Stage E, sandbox only until approved)
```
purchases(id text pk, user_id text, provider text check (provider in ('apple','google','web','test')),
  product_id text, provider_transaction_id text not null, original_transaction_id text,
  state text check (state in ('pending','purchased','canceled','refunded','revoked')),
  raw_status jsonb, verified_at timestamptz, acknowledged_at timestamptz, consumed_at timestamptz,
  unique (provider, provider_transaction_id))
entitlements(id text pk, user_id text, kind text check (kind in ('coins','bundle','season_pass')),
  purchase_id text references purchases(id), granted_at timestamptz, revoked_at timestamptz,
  unique (purchase_id, kind))
ledger: kind += 'purchase_credit','purchase_refund'; currency_origin text default 'granted'
```
Coins from a purchase: `ledger.idem_key = 'purchase:' || provider || ':' || provider_transaction_id`. Restore never
re-credits consumables. Refund writes a counter-entry; if the balance is insufficient the shortfall is recorded per policy
(docs/MONETIZATION_READINESS.md), the wallet never goes negative.

## Recovery and rollback

- Each migration has a matching `down` note in the migration file header and is tested on a copy of the database
  (create, migrate up, run tests, roll back, migrate up again).
- Reward and purchase flows are restart-safe: the outcome row is committed before any client effect; reconciliation jobs
  re-read pending purchases and unclaimed rewards on boot.
- Ledger consistency check (`assertLedgerConsistent` in tests) extends to every new kind.
